## 2. 시연 대본 (FE1 파트 약 3분)

**준비**
- 실제 백엔드 연결: `.env.local` 에 `VITE_USE_MOCK=false` → `npm run dev`
- 백엔드가 불안하면 목 서버(`VITE_USE_MOCK=true`)로 같은 흐름을 그대로 시연할 수 있어요
- 브라우저 확대 100%, 시연 전 `npm run test:e2e` 로 한 번 점검
- 새로 가입할 이메일을 미리 정해 두기 (예: `demo1215@petplanet.kr`)

| 단계 | 누를 것 | 말할 것 |
|---|---|---|
| ① 가입 (S09) | 헤더 [로그인] → [회원가입] → 이메일 입력 → [중복 확인] → 비밀번호(조건 체크가 초록으로 바뀌는 것 보여주기) → 이름 → 일반 회원 → 반려동물 보리·진돗개·18kg·수컷·완료 → [가입하고 출발하기] | "계정과 첫 반려동물을 한 번에, 하나의 트랜잭션으로 저장해요." |
| ② 홈 (S01) | 체중 배너 보여주기 | "등록한 18kg이 객실 최대 몸무게와 바로 비교돼요. 미디엄 룸은 입실 불가." |
| ③ 탐색 (S02) | [우리 역 주변 찾기] → 2호선 · 홍대입구 → 카테고리 [카페] → 크기 [소형] → 지도 핀 클릭 | "역 반경 1km 장소를 미리 계산해 둔 거리로 가까운 순으로 보여줘요. 핀 번호와 카드 번호가 같아요." |
| ④ 상세 (S03) | 카드 클릭 → [관심 장소 찜하기] → NOW STATION 마지막 역 | "같은 장소는 두 번 찜할 수 없게 DB에서 막아요." |
| ⑤ 리뷰 | [리뷰 쓰기] → 별점 5 → 후기 → [리뷰 등록] → 별점·리뷰 수 바뀐 것 | "평균 별점이 바로 다시 집계돼요." |
| ⑥ 마이페이지 (S08) | 헤더 [마이페이지] → 요약 타일 → 작성한 리뷰 · 찜한 장소 | "예약·주문·리뷰·찜을 한곳에서 보는 환승센터예요." → R·S 파트로 넘기기 |

**막혔을 때**
| 상황 | 대처 |

| 서버 연결 끊김 (화면에 "연결이 끊겼어요") | `.env.local` 을 `VITE_USE_MOCK=true` 로 바꾸고 dev 서버 재시작 → 같은 흐름 |

## 3. 예상 질문과 답변 (FE1)

| 질문 | 답변 |
|---|---|
| 역 반경 1km는 어떻게 계산했나요? | 위도·경도로 하버사인 공식을 써서 장소마다 1km 안의 역과 거리를 미리 계산해 `place_stations` 에 저장해요(N:M). 검색할 때는 다시 계산하지 않고 이 표를 조인해서 빨라요. 0.5km 필터는 `distance_km <= 0.5` 조건이에요. |
| 다중 필터는 SQL로 어떻게 되나요? | 카테고리 IN, 동반 가능 크기(선택한 크기 이상 허용하는 곳), 실내외 IN, 거리 조건을 WHERE 에 함께 넣고, 정렬은 거리 또는 리뷰 수(COUNT) 순이에요. |
| 같은 장소를 두 번 찜하면? | `place_bookmarks` 에 UNIQUE(user_id, place_id)가 있어서 DB가 막고, API는 409를 돌려줘요. 화면은 이미 찜한 상태로 맞춰요. |
| 백엔드가 없을 때는 어떻게 개발했나요? | API 명세대로 똑같이 응답하는 목 서버를 프론트 안에 만들었어요. 설정 하나(`VITE_USE_MOCK`)로 실제 API와 바꿔요. 그래서 FE·BE가 동시에 개발할 수 있었어요. |
| 에러 처리는 어떻게 했나요? | 모든 API 에러를 `{status, code, message, errors}` 한 모양으로 맞추고, 프론트는 한 곳에서 처리해요. 입력 오류는 해당 칸 아래, 로그인 만료(401)는 자동 로그아웃, 네트워크 끊김은 안내 띠와 다시 시도 버튼. |
| 회원가입과 반려동물 등록을 왜 한 번에? | 반려동물 체중이 있어야 호텔 객실 검증이 되기 때문에, 계정과 첫 반려동물을 한 트랜잭션으로 저장해 "반려동물 없는 회원"이 생기지 않게 했어요. |
| 비밀번호는 안전한가요? | 프론트는 조건(8~20자, 영문·숫자·특수문자)을 검사하고, 서버에서 단방향 암호화(BCrypt 등)해서 저장해요. 로그인 후에는 JWT 토큰으로 인증해요. |
| 리뷰 평균 별점은 어떻게? | `reviews` 에서 대상별로 `ROUND(AVG(rating),1)`, `COUNT(*)` 집계. 등록·수정·삭제 후 다시 불러와 바로 반영해요. |
| 디자인 일관성은 어떻게 유지했나요? | 색·폰트를 토큰으로 정하고 헤더, NOW STATION, 선택 버튼, 카드 같은 공통 컴포넌트를 만들어 FE 두 명이 같이 써요. 목업 규칙(4색, 주요 버튼 1개)을 코드로 고정했어요. |
| 모바일은? | 화면 폭에 따라 배치가 바뀌는 반응형이에요. 390px(휴대폰)·768px(태블릿)·1440px(PC)에서 점검했어요. |
| 테스트는 어떻게 했나요? | 단위·통합 테스트 15개(`npm run test:unit`)와 시연 시나리오를 브라우저로 따라가는 자동 점검 28개 항목(`npm run test:e2e`). |
